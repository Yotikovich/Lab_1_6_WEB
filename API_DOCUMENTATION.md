# Event Management API

REST API інформаційної системи управління подіями. Усі маршрути `/api/events` потребують JWT access token у заголовку `Authorization: Bearer <token>`.

## Події

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/events?search=назва&page=1&limit=10` | Список подій, пошук і пагінація |
| POST | `/api/events` | Створення події |
| GET | `/api/events/:id` | Детальна інформація про подію |
| PUT | `/api/events/:id` | Редагування події |
| DELETE | `/api/events/:id` | Видалення події та пов’язаних записів |

Статуси події: `DRAFT`, `PUBLISHED`, `CANCELLED`, `COMPLETED`. Завершення повинно бути пізніше початку. Організатор працює зі своїми подіями, адміністратор має доступ до всіх.

### Створення події

`POST /api/events`

```json
{
  "title": "IT Conference 2026",
  "description": "Конференція про сучасні вебтехнології",
  "status": "PUBLISHED",
  "startsAt": "2026-12-10T09:00:00.000Z",
  "endsAt": "2026-12-10T18:00:00.000Z",
  "venueId": 1,
  "capacity": 250
}
```

## Учасники та реєстрації

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/events/participants` | Перелік учасників |
| POST | `/api/events/participants` | Створити або оновити учасника за email |
| PUT | `/api/events/participants/:id` | Редагувати учасника |
| DELETE | `/api/events/participants/:id` | Видалити учасника та його реєстрації |
| GET | `/api/events/registrations` | Перелік реєстрацій організатора |
| GET | `/api/events/registrations?eventId=1` | Реєстрації конкретної події |
| PATCH | `/api/events/registrations/:id/cancel` | Скасувати реєстрацію та квиток (якщо квиток ще не використано) |
| PATCH | `/api/events/tickets/:id/check-in` | Позначити дійсний квиток використаним під час входу |
| POST | `/api/events/:id/registrations` | Зареєструвати учасника та видати квиток |

Створення учасника (`POST /api/events/participants`):

```json
{
  "name": "Іван Петренко",
  "email": "ivan@example.com",
  "phone": "+380501234567"
}
```

Реєстрація (`POST /api/events/:id/registrations`):

```json
{
  "participantId": 1,
  "ticketTypeId": 1
}
```

Реєстрація дозволена для опублікованих подій. Перевіряється місткість події, доступна кількість квитків та унікальність пари «подія — учасник». Повторна реєстрація повертає `409 Conflict`.

## Типи квитків

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/events/:id/ticket-types` | Перелік типів квитків |
| POST | `/api/events/:id/ticket-types` | Створити тип квитка |
| PUT | `/api/events/:id/ticket-types/:ticketTypeId` | Редагувати тип квитка |
| DELETE | `/api/events/:id/ticket-types/:ticketTypeId` | Видалити тип, якщо для нього не створювали квитки |

```json
{
  "name": "Стандартний",
  "description": "Доступ до основної програми",
  "price": 500,
  "quantity": 150
}
```

Після реєстрації система створює квиток з унікальним кодом. Для контролю входу організатор може виконати `PATCH /api/events/tickets/:id/check-in`; повторне використання або скасований квиток повертає `409 Conflict`. Якщо реєстрацію скасовано, повторна реєстрація того самого учасника відновлює її та створює новий квиток. Видалити тип квитка, для якого вже створювалися квитки, не можна — це зберігає історію виданих квитків.

## Розклад

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/events/:id/schedule` | Отримати розклад події |
| POST | `/api/events/:id/schedule` | Додати пункт програми |
| PUT | `/api/events/:id/schedule/:itemId` | Редагувати пункт програми |
| DELETE | `/api/events/:id/schedule/:itemId` | Видалити пункт програми |

```json
{
  "title": "Відкриття конференції",
  "description": "Вітальне слово організаторів",
  "startsAt": "2026-12-10T09:00:00.000Z",
  "endsAt": "2026-12-10T09:30:00.000Z",
  "speaker": "Організаційний комітет",
  "location": "Головна зала"
}
```

Час пункту програми має бути в межах часу відповідної події. Під час редагування перевірка виконується повторно.

## Службові маршрути

- `GET /api/health` — перевірка доступності сервера.
- `/api/auth/*` — реєстрація, вхід, оновлення токена та профіль.
- `/api/users/*` — керування обліковими записами.
- `/api/notifications/*` — сповіщення.
- `/api-docs/` — інтерактивна документація Swagger.

Успішні відповіді повертають JSON. Помилки валідації — `400`, відсутні записи — `404`, конфлікти реєстрації або нестача квитків — `409`.
