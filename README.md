# Event Management System

Вебзастосунок для управління подіями: створення та облік подій, учасників, квитків, локацій і розкладу.

## Технології

- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS
- **Backend:** Node.js, Express.js
- **База даних:** PostgreSQL, Prisma ORM
- **Авторизація:** JWT, Argon2id
- **API:** REST, Swagger
- **Реальний час:** Socket.IO (статус користувачів онлайн та кімнати подій)

## Основні можливості

- Реєстрація, вхід і рольова авторизація.
- Створення, перегляд, пошук та редагування подій.
- Облік локацій проведення.
- Реєстр учасників.
- Типи квитків, ціна, кількість, унікальні коди та відмітка використання квитка під час входу.
- Реєстрація учасників на події, скасування реєстрацій та видача квитків.
- Розклад подій із доповідачами та місцями проведення.
- Панель керування та сповіщення.

## Структура предметної області

| Сутність | Призначення |
|---|---|
| User | Обліковий запис організатора або адміністратора |
| Event | Подія, її опис, статус, час і місткість |
| Venue | Локація проведення |
| Participant | Учасник подій |
| Registration | Реєстрація учасника на подію |
| TicketType | Категорія квитка, ціна та кількість |
| Ticket | Виданий квиток з унікальним кодом |
| Schedule | Пункт програми події |

## Запуск локально

### 1. Вимоги

- Node.js 20.19 або новіше (або Node.js 22.12+)
- PostgreSQL
- npm

### 2. Налаштування сервера

Скопіюйте `.env.example` у `.env` у корені проєкту. Для швидкого запуску PostgreSQL через Docker виконайте `docker compose up -d`. Compose використовує значення `POSTGRES_PASSWORD` із `.env`. Якщо PostgreSQL уже встановлений локально, змініть `DATABASE_URL` відповідно до власних параметрів.
Встановіть залежності та згенеруйте Prisma Client:

```bash
npm install
npm run db:generate
npm run db:deploy
```

Команда `db:deploy` застосовує всі міграції PostgreSQL у правильному порядку, включно з видаленням старих таблиць Task Management. Якщо у старій базі є потрібні дані завдань, зробіть резервну копію перед застосуванням міграції.

### Створення адміністратора

За потреби задайте `ADMIN_NAME`, `ADMIN_EMAIL` та `ADMIN_PASSWORD` у `.env`, після чого виконайте:

```bash
npm run db:seed
```

Команда створить адміністратора або оновить наявний обліковий запис із таким email. Пароль зберігається у вигляді хешу Argon2id. Не використовуйте наведений у прикладі пароль у реальному середовищі.

### Запуск API

```bash
npm run dev
```

Сервер: `http://localhost:3000`  
Swagger: `http://localhost:3000/api-docs/`  
Перевірка стану: `http://localhost:3000/api/health`

### 3. Запуск клієнта

```bash
cd client
npm install
```

Скопіюйте `client/.env.example` у `client/.env` (або створіть файл вручну):

```env
VITE_API_URL=http://localhost:3000/api
VITE_SOCKET_URL=http://localhost:3000
```

Запустіть клієнт:

```bash
npm run dev
```

## API

Основні маршрути описані у файлі [API_DOCUMENTATION.md](./API_DOCUMENTATION.md). Усі маршрути `/api/events` захищені JWT-авторизацією.

## Структура та доступ

- Організатор бачить і редагує власні події.
- Адміністратор має доступ до всіх подій.
- Локації та реєстр учасників доступні авторизованим користувачам системи.
- Для реєстрації потрібна опублікована подія, активний тип квитка та вільна місткість.
- Socket.IO підтримує presence користувачів і кімнати `event:join` / `event:leave` із перевіркою прав організатора.
- Повторна активна реєстрація одного учасника на ту саму подію заборонена. Скасовану реєстрацію можна відновити повторною реєстрацією.
- Оплата квитків не інтегрована: квитки створюються як записи в базі даних із унікальними кодами.

Архів початкових звітів Task Management збережено окремо в `archive/task-management-reports` і він не використовується застосунком. Старі таблиці Task Management видаляються окремою міграцією `20261123200000_remove_task_management`. Це очищає схему від старої предметної області; якщо в попередній базі є важливі дані, перед міграцією обов’язково створіть резервну копію.

## Перевірка

Після встановлення залежностей можна виконати `npm run check` для базової перевірки синтаксису серверного коду. Повні інтеграційні тести потребують доступної PostgreSQL-бази та налаштованого `.env` (`npm test`). Клієнтська production-збірка: `cd client && npm run build`.
