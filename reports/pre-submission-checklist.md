# Перевірка перед демонстрацією викладачеві

## Перший запуск

- [ ] Скопіювати `.env.example` у `.env` і змінити `JWT_SECRET` та пароль PostgreSQL.
- [ ] Запустити PostgreSQL: `docker compose up -d` або використати локальний сервер PostgreSQL.
- [ ] У корені проєкту виконати `npm install`.
- [ ] Згенерувати Prisma Client: `npm run db:generate`.
- [ ] Застосувати міграції: `npm run db:deploy`.
- [ ] Створити адміністратора: `npm run db:seed`.
- [ ] Запустити backend: `npm run dev`.
- [ ] У `client` встановити залежності, скопіювати `.env.example` у `.env` та запустити `npm run dev`.

## Сценарій демонстрації

1. Увійти під обліковим записом адміністратора.
2. Створити локацію з адресою та місткістю.
3. Створити подію, призначити локацію, час і місткість.
4. Створити тип квитка з ціною та кількістю.
5. Додати кілька пунктів розкладу з доповідачем і часом.
6. Створити учасника та зареєструвати його на опубліковану подію.
7. Показати унікальний код квитка та відмітити квиток як використаний.
8. Спробувати повторно використати квиток — система має відмовити.
9. Показати пошук, редагування та скасування реєстрації.
10. Відкрити Swagger: `http://localhost:3000/api-docs/`.

## Команди перевірки

У корені проєкту:

```bash
npm run check
npm test
```

У папці `client`:

```bash
npm run build
npm run lint
```

Інтеграційні тести потребують запущеної PostgreSQL і налаштованого `.env`. Якщо база вже містить дані з Task Management, зробіть резервну копію перед `npm run db:deploy`: фінальна міграція видаляє старі таблиці `Project`, `Task` і `Comment`.
